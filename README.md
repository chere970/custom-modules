# Odoo 19 Development Workspace

Local training environment for building custom Odoo modules on Ubuntu using Python virtual environments and PostgreSQL.

---

## Directory Overview

```text
odoo-training/
├── config/
│   └── odoo.conf             # Instance configuration (addons paths, db connection, ports)
├── custom-addons/
│   ├── estate/               # Custom real estate property management module
│   │   ├── models/           # Python ORM data models (real.estate)
│   │   ├── views/            # Form, list, search, and menu XML definitions
│   │   ├── security/         # User/Manager groups (res_group.xml) and ACLs (ir.model.access.csv)
│   │   └── __manifest__.py   # Module metadata, dependencies, and data loading order
│   └── school_management/    # Custom school management module
└── odoo/                     # Odoo 19 Community source repository
    ├── .venv/                # Dedicated Python virtual environment
    └── odoo-bin              # Odoo execution entrypoint


Prerequisites

    OS: Ubuntu 22.04 LTS / 24.04 LTS

    Python: Python 3.10+ (inside .venv)

    Database: PostgreSQL running locally

    Core Framework: Odoo 19.0 Community Edition

Quick Start
1. Activate Environment

    cd ~/odoo-training/odoo
    source .venv/bin/activate

2. Start Odoo Server
    ./odoo-bin -c ~/odoo-training/config/odoo.conf -d odoo_training

Access the web interface at: http://localhost:8069


# Development Commands
Upgrade a Module (Apply Python & XML Changes)

Run the update flag whenever you modify models, access rules, or view architectures:

    ./odoo-bin -c ~/odoo-training/config/odoo.conf -d odoo_training -u estate

Install a New Module

    ./odoo-bin -c ~/odoo-training/config/odoo.conf -d odoo_training -i estate


# Development Guidelines

    List Views: Use <list> as the primary architecture tag (the legacy <tree> tag is deprecated in Odoo 19).

    Access Rights: Ensure models in ir.model.access.csv match the technical name generated by the ORM (e.g., model_real_estate for _name = "real.estate").

    Manifest Loading Order: Actions and security groups must always precede menus and views that reference them.
